

### TrainHub — система учета корпоративного обучения.

### Назначение
TrainHub предназначен для автоматизации базового учета обучения сотрудников внутри компании. Система заменяет Excel-таблицы и позволяет в удобном веб-интерфейсе вести каталог учебных курсов, назначать их сотрудникам и отслеживать статус прохождения. Главная цель учебного проекта — продемонстрировать навыки проектирования БД, разработки бэкенда и создания пользовательского интерфейса для решения реальной бизнес-задачи.

### Целевую аудиторию
В рамках учебного проекта выделены две основные роли:
1. **Администратор (HR-менеджер):** управляет базой сотрудников, добавляет новые курсы в каталог, назначает обучение и просматривает общую статистику.
2. **Сотрудник:** заходит в личный кабинет, видит список назначенных ему курсов, их deadlines (сроки сдачи) и отмечает факт прохождения.

### Описание предметной области
В любой компании сотрудников необходимо обучать: инструктажи по охране труда, введение в должность, повышение квалификации. 
В небольших компаниях этот процесс часто ведется хаотично: HR-менеджер вручную рассылает письма, а статус прохождения отслеживает в таблице. Из-за этого теряются данные, сотрудники забывают о сроках, а руководитель не видит общей картины. 
Предметная область проекта охватывает процесс **назначения курса -> прохождения курса -> фиксации результата**. TrainHub оцифровывает этот простой жизненный цикл обучающего мероприятия.

### Основные сущности
Для учебного проекта база данных максимально упрощена и состоит из трех ключевых таблиц:

1. **Пользователь (User)**
   * `id`, `ФИО`, `email`, `пароль` (хэш), `роль` (админ / сотрудник), `должность`.
2. **Курс (Course)**
   * `id`, `название`, `описание`, `тип` (онлайн/очно), `обязательность` (да/нет), `срок прохождения` (в днях).
3. **Назначение (Enrollment)** *(связующая сущность)*
   * `id`, `id_пользователя`, `id_курса`, `дата_назначения`, `дедлайн`, `статус` (назначено / в процессе / завершено), `оценка/результат` (опционально).


### Основные функции
Функционал сокращен до необходимого минимума для защиты проекта:

**Для Администратора:**
* **Авторизация** и разграничение прав доступа.
* **CRUD сотрудников:** добавление, редактирование и удаление пользователей.
* **CRUD курсов:** создание карточки нового курса и редактирование каталога.
* **Назначение обучения:** выбор сотрудника (или списка) и привязка к нему курса с указанием дедлайна.
* **Сводная таблица:** просмотр списка всех назначений с возможностью фильтрации по статусу (например, показать только просроченные).

**Для Сотрудника:**
* **Личный кабинет:** просмотр списка "Мои курсы".
* **Смена статуса:** кнопка "Отметить как пройденное" (или ввод результата/оценки).

### План развития проекта
План составлен с учетом этапов стандартной разработки учебного проекта (от ТЗ до защиты):

**Этап 1. Проектирование (1-2 недели)**
* Анализ предметной области и сбор требований.
* Проектирование ER-диаграммы базы данных (3 основные сущности).
* Создание макетов интерфейса (wireframes) в Figma.

**Этап 2. Разработка бэкенда и БД (2-3 недели)**
* Развертывание локальной БД (PostgreSQL/MySQL).
* Настройка ORM и создание моделей (User, Course, Enrollment).
* Реализация API/контроллеров для CRUD-операций и аутентификации (JWT или сессии).

**Этап 3. Разработка фронтенда (2-3 недели)**
* Верстка базового шаблона (меню, хедер).
* Создание форм для добавления курсов и пользователей.
* Реализация личных кабинетов и таблиц с данными.
* Связывание фронтенда с бэкендом.

**Этап 4. Тестирование и подготовка к защите (1-2 недели)**
* Написание тестов (unit-тесты для базовых функций).
* Ручное тестирование сценариев (создать курс -> назначить -> пройти).
* Написание пояснительной записки / документации.
* Подготовка презентации и демо-стенда для защиты проекта.
