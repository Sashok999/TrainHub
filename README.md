# TrainHub — система учета корпоративного обучения

Консольное приложение для автоматизации учета учебных курсов, управления сотрудниками и процессом корпоративного обучения.

## Назначение
TrainHub предназначен для автоматизации базового учета обучения сотрудников внутри компании. Система позволяет вести каталог учебных курсов, регистрировать сотрудников, назначать обучение на определенные даты, проверять доступность и отслеживать статус прохождения.

Приложение позволяет:
* просматривать и искать курсы в каталоге;
* проверять соответствие длительности курса временным лимитам;
* сортировать курсы по длительности;
* вести список сотрудников компании и осуществлять поиск по ним;
* проверять доступность курса для сотрудника на выбранную дату;
* создавать назначения на обучение (запись на курс);
* отменять назначения на обучение;
* просматривать сводный реестр всех назначений;
* сохранять и загружать данные между запусками программы в формате JSON.

## Целевая аудитория
* **HR-менеджеры и специалисты по обучению (L&D):** формируют учебные планы, ведут базу сотрудников и контролируют процесс обучения.
* **Руководители отделов и сотрудники:** просматривают назначенные курсы и сроки их прохождения.

## Предметная область
Предметная область охватывает процесс **добавления курса -> выбора сотрудника -> назначения курса -> контроля статуса**.
Основными объектами предметной области являются:
* **Курс (Course)**;
* **Пользователь / Сотрудник (User)**;
* **Назначение (Enrollment)**.

Сотрудник может быть назначен на курс на определенную дату.
Один сотрудник не может иметь два активных назначения на один и тот же курс на одну дату.
Отмененное назначение не блокирует курс и позволяет создать новое назначение на эту дату.

## Основные сущности

### Course — учебный курс
Объект `Course` представляет учебную программу или инструктаж в каталоге.
**Основные атрибуты:**
* `id` — уникальный идентификатор курса;
* `name` — наименование курса;
* `description` — подробное описание курса;
* `duration_days` — длительность прохождения в днях;
* `course_type` — формат обучения (`онлайн` / `очно`);
* `is_mandatory` — признак обязательности прохождения.

**Основные методы:**
* `is_suitable_for(max_days)` — проверка, укладывается ли длительность курса в лимит;
* `validate_duration(duration_days)` (`@staticmethod`) — валидация корректности длительности;
* `from_data(data)` (`@classmethod`) — создание объекта курса из словаря данных;
* `to_dict()` — сериализация объекта курса в словарь для JSON;
* `__str__()` — удобное строковое представление курса.

### User — пользователь / сотрудник
Объект `User` представляет сотрудника организации.
**Основные атрибуты:**
* `id` — уникальный идентификатор сотрудника;
* `name` — ФИО сотрудника;
* `email` — рабочий адрес электронной почты;
* `position` — должность сотрудника;
* `role` — роль в системе (`сотрудник` / `админ`).

**Основные методы:**
* `validate_email(email)` (`@staticmethod`) — проверка валидности email;
* `from_data(data)` (`@classmethod`) — фабричный метод создания объекта `User`;
* `to_dict()` — сериализация пользователя в словарь для JSON;
* `__str__()` — строковое представление сотрудника.

### Enrollment — назначение на обучение
Объект `Enrollment` связывает сотрудника и курс, фиксируя дату и статус обучения.
**Основные атрибуты:**
* `id` — уникальный идентификатор назначения;
* `course` — объект класса `Course`;
* `enrollment_date` — дата назначения на обучение;
* `user` — объект класса `User`;
* `is_cancelled` — флаг отмены назначения;
* `is_completed` — флаг успешного завершения обучения.

**Основные методы и свойства:**
* `cancel()` — отмена назначения курса;
* `complete()` — отметка курса как пройденного;
* `status` (`@property`) — вычисляемый текстовый статус (`Активно`, `Завершено`, `Отменено`);
* `to_dict()` — сериализация в словарь с сохранением `course_id` и `user_id`;
* `__str__()` — строковое представление назначения со статусом.

## Взаимодействие объектов
Объект `Enrollment` содержит прямые ссылки на объекты `Course` и `User`, а не просто числовые идентификаторы:
```text
Enrollment
├── course ──> Course
└── user   ──> User
```
Благодаря этому данные связанных сущностей доступны напрямую:
* `enrollment.course.name`
* `enrollment.course.duration_days`
* `enrollment.user.name`
* `enrollment.user.email`

## Хранение данных
Данные приложения хранятся в JSON-файлах в директории `data/`:
* `data/courses.json` — каталог курсов;
* `data/users.json` — реестр сотрудников;
* `data/enrollments.json` — назначения на обучение (сохраняются `course_id` и `user_id`).

При загрузке JSON-структуры преобразуются в полноценные объекты классов `Course`, `User` и `Enrollment` с восстановлением связей. При сохранении выполняется обратное преобразование.

## Назначение модулей
* **`main.py`** — консольный интерфейс, обработка пользовательских сценариев, оркестрация объектов.
* **`models/courses.py`** — класс `Course`, функции поиска, фильтрации, сортировки и отображения курсов.
* **`models/users.py`** — класс `User`, функции добавления, поиска и отображения сотрудников (включая функцию `show_employees` из ПР1).
* **`models/enrollments.py`** — класс `Enrollment`, функции проверки доступности, регистрации на курс (`register_on_courses`), отмены и вывода.
* **`storage.py`** — безопасное чтение и запись JSON-файлов с использованием контекстных менеджеров `with` и обработкой исключений.
* **`utils.py`** — функции безопасного ввода (`input_int`, `input_date`, `input_non_empty_str`) с валидацией и перехватом `ValueError`.
* **`tests/`** — набор модульных тестов для проверки всех сущностей, методов и сценариев взаимодействия.

## Требования
* Python 3.10+;
* pytest >= 8.0;
* flake8 >= 7.0.

## Установка зависимостей
```bash
pip install -r requirements.txt
```

## Запуск приложения
```bash
python main.py
```

## Запуск тестов
Для запуска автоматизированных тестов выполните:
```bash
pytest -v
```

## Проверка качества кода
Для проверки кода на соответствие стандарту PEP 8 выполните:

1. Разработка веб-приложения на базе фреймворка (Django / FastAPI).
2. Подключение реляционной базы данных (PostgreSQL / SQLite).
3. Создание REST API для интеграции с внешними корпоративными сервисами.
4. Разграничение прав доступа и ролевая модель (HR-администратор / сотрудник).
5. Контейнеризация с использованием Docker.
6. Настройка автоматизированного пайплайна CI/CD.
